# 10｜VPS 数据备份与恢复规划

备份的价值在于发生故障后能够恢复。只创建备份文件而从不验证恢复流程，并不能证明数据可恢复。

## 1. 先确定备份范围

常见备份对象：

- 网站文件；
- 应用配置；
- 数据库；
- 上传文件和用户生成内容；
- TLS 证书及续期配置（按安全要求保护）；
- 部署脚本和基础设施配置；
- 业务所需的密钥材料（必须加密并严格限制访问）。

不要把临时缓存、可重建文件和必须保留的数据混为一谈。

## 2. 制定备份策略

可从以下维度制定规则：

- 备份频率；
- 保留周期；
- 本地与异地副本；
- 加密方式；
- 访问权限；
- 备份失败告警；
- 恢复目标时间（RTO）；
- 可接受的数据丢失窗口（RPO）。

具体频率取决于数据变化速度和业务要求。

## 3. rsync 示例

`examples/backup-example.sh` 提供目录同步示例。执行前必须修改源目录和备份目标，并确认目标路径正确。

rsync 同步不是完整的数据库一致性备份方案。数据库应使用对应数据库工具或经过验证的快照流程。

## 4. 备份安全

- 备份应限制访问权限；
- 重要备份应加密；
- 异地保存副本；
- 防止生产账户可随意删除所有备份；
- 备份凭据与生产凭据分开管理；
- 定期检查备份任务结果。

## 5. 恢复演练

至少定期验证：

1. 能否读取备份；
2. 文件是否完整；
3. 数据库能否恢复；
4. 应用配置是否齐全；
5. DNS、证书和网络是否需要重新配置；
6. 恢复后业务是否正常。

## 6. 相关提醒

服务商快照不一定等于应用一致性备份，也不一定覆盖所有数据盘。应确认快照范围、保留周期、恢复流程和费用。
