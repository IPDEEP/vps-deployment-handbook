# 08｜Nginx 网站部署与反向代理基础

Nginx 是常见的 Web 服务器和反向代理软件。它可以接收客户端请求，再根据配置提供静态文件或将请求转发给后端应用。

## 1. 安装 Nginx

Debian / Ubuntu 示例：

```bash
sudo apt update
sudo apt install nginx
```

其他发行版请使用对应包管理器和官方软件源说明。

## 2. 检查服务状态

```bash
sudo systemctl status nginx
```

检查配置语法：

```bash
sudo nginx -t
```

重新加载配置：

```bash
sudo systemctl reload nginx
```

应先确保 `nginx -t` 通过，再执行 reload。

## 3. 示例站点配置

仓库 `examples/nginx-site.conf` 提供一个基础示例。部署前请替换域名、站点目录和后端地址，并检查发行版的 Nginx 配置目录结构。

## 4. 反向代理的基本概念

反向代理由 Nginx 接收外部请求，再转发给内部应用。例如，外部访问 80 / 443 端口，应用在本机的 3000 端口监听。

示意：

```text
浏览器
  |
  v
Nginx :80 / :443
  |
  v
应用服务 127.0.0.1:3000
```

后端应用应尽可能只监听所需的内部接口，避免不必要地暴露管理端口。

## 5. 域名和 HTTPS

上线前需要：

1. 确认域名解析指向正确服务器；
2. 确认防火墙和云安全组允许所需端口；
3. 配置 TLS 证书；
4. 设置证书续期和到期监控；
5. 检查 HTTP 到 HTTPS 的跳转策略；
6. 验证站点日志和错误响应。

证书申请和续期方式会随域名、系统和证书服务商不同而变化。

## 6. 常见问题

- 502：后端应用不可用、地址错误或连接被拒绝；
- 403：权限、访问规则或目录索引配置问题；
- 404：路径或站点路由配置问题；
- 证书错误：域名、证书链或有效期问题。
