# 11｜VPS 常见故障排查

排查服务器问题时，先确定故障范围，再查看资源、服务状态、网络和日志。不要在没有证据时直接重装系统。

## 1. SSH 无法连接

检查：

- IP 地址和端口是否正确；
- SSH 服务是否运行；
- 云平台安全组是否允许；
- 系统防火墙是否放行；
- 用户名和认证方式是否正确；
- 本地网络是否能够到达服务器。

可使用服务商控制台或救援模式进行带外检查。

## 2. 网站打不开

按顺序检查：

1. 域名解析是否指向预期地址；
2. 云安全组和系统防火墙是否允许 80 / 443；
3. Nginx 或其他 Web 服务是否运行；
4. 配置语法是否通过；
5. 后端应用是否正常；
6. TLS 证书是否有效；
7. 查看访问日志和错误日志。

## 3. 502 Bad Gateway

常见原因：

- 后端应用未启动；
- Nginx upstream 地址或端口错误；
- 后端只监听了不同接口；
- 本机防火墙阻断；
- 应用处理请求过慢或崩溃。

应同时检查 Nginx 错误日志和后端应用日志。

## 4. 磁盘空间不足

```bash
df -h
df -i
du -xhd1 /
```

`du` 的参数支持情况可能因系统版本而异。删除日志或数据前，先确认文件用途、保留要求和是否仍被进程占用。

## 5. CPU 或内存异常

使用 `top`、`free -h` 和系统日志查看异常进程。确认是否为正常流量增长、程序泄漏、任务堆积或异常访问。

不要仅凭进程名称就结束关键系统服务。

## 6. 网络延迟或丢包

确认测试源、目标、时间段和网络路径。可以结合 `ping`、`traceroute` / `tracepath`（如已安装）和服务商监控数据判断。部分网络会限制 ICMP，因此单一 ping 结果不能代表全部业务连接。

## 7. 处理原则

- 先采集信息，再修改配置；
- 一次只改一个关键变量；
- 记录修改前后的状态；
- 保留控制台救援入口；
- 有备份后再做高风险操作；
- 不公开分享凭据和敏感日志。
