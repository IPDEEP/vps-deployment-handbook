# 09｜VPS 服务器监控与资源检查

服务器监控的目的不是只看某一时刻的 CPU 百分比，而是持续观察资源趋势、错误日志和业务可用性。

## 1. CPU

```bash
top
```

部分发行版可安装 `htop` 提供交互式视图。需要关注持续高负载、进程异常和负载平均值，而不是只看瞬时数字。

## 2. 内存

```bash
free -h
```

同时观察 Swap 使用和进程内存。Linux 会利用空闲内存做缓存，因此不能仅凭“used”数值判断内存不足。

## 3. 磁盘

```bash
df -h
du -sh /var/log
lsblk
```

磁盘空间不足可能导致日志、数据库、应用写入失败。还应关注 inode 使用情况：

```bash
df -i
```

## 4. 网络与连接

可以根据系统安装情况使用：

```bash
ss -tulpen
ip addr
ip route
```

这些命令帮助查看监听端口、网络接口和路由信息。输出可能包含内部网络信息，公开分享前应脱敏。

## 5. 服务日志

systemd 服务常见查看方式：

```bash
journalctl -u nginx --since "1 hour ago"
```

将服务名替换为实际服务。日志中可能含有 IP、路径、令牌或用户信息，分享前应检查。

## 6. 建议监控的指标

- CPU 使用率与负载；
- 内存和 Swap；
- 磁盘空间与 inode；
- 网络吞吐和丢包；
- 服务进程状态；
- HTTP 响应状态与延迟；
- 证书到期时间；
- 备份任务结果。

## 7. 建立告警阈值

阈值应根据业务基线、峰值和恢复能力设定。不要照搬其他服务器的固定阈值。告警需要有负责人、处理步骤和升级机制。
